What the checker does

The tool hunts configuration files and running processes for credentials left at their factory defaults, run as python3 main.py -c CONFIG [-v]. The YAML configuration file is required and is the only way in. It is validated against a schema before anything is scanned: a files list is required, and processes, credentials, and regex lists are optional additions. Invalid config regexes are compiled once up front, and an invalid one exits 1 before any file is scanned.

The built in dictionary

The built in dictionary is small and exact: the usernames admin, user, root, and test, and the passwords password, 123456, admin, test, password123, and changeme. Configuration credentials extend it.

Matching

File matching is whole-token and case-insensitive, so a dictionary word inside a longer word does not flag. Process matching is the opposite: exact-name and case-sensitive via psutil, so a service listed under a different capitalisation is silently never checked.

Files are read with undecodable bytes dropped rather than failing, so a binary holding one readable credential line still gets scanned with characters quietly lost. A configured file that does not exist marks the whole scan failed and the run exits 1.

Findings and masking

In a finding, the matched dictionary value stays visible in the Value field as public dictionary material, while every other value shaped token on the line is masked, so a non-default credential sharing the line does not print in clear.

Parameters

  • -c, --config: path to the YAML configuration file. Required.
  • -v: verbose output.

The README parameter list describes -c but leaves -v undescribed, though the code help text describes it. That record stands as printed.

Exit codes

Findings exit 1 and a clean scan exits 0. A missing configured file, a failed scan, or an invalid custom pattern also ends the run at exit 1, the pattern case before any file is scanned.
