What Counts as a Hit

The program checks named files and named running processes for default or weak credentials. It uses a built in dictionary holding two credential types, named username and password, and regular expressions supplied in its configuration. Credential values are never printed as examples on this page; types and behaviours are stated as facts only. Matching is by whole token, not by substring, and case is ignored: a value inside a longer word does not count as a hit, and a key name alone does not count as a value hit. Patterns are compiled once, before scanning starts, and an invalid pattern ends the run at exit 1 before any file is scanned.

The Configuration

One option is required: the path to a YAML configuration file, given in short or long form. The schema in the code requires a files list. Processes are optional. A credentials section is optional, with optional username and password lists. A regex list is optional. Custom entries are merged into the built in dictionary by extending copies of its lists; the original lists are not altered for later calls.

Files and Processes

Each configured file is read as UTF 8 text, with undecodable bytes dropped rather than failing the file. Each line is tested against the dictionary and against each pattern, and a finding names the file, the line number, the credential type or the pattern, and the line content in masked form. A configured file that does not exist marks the scan as failed and the run ends at exit 1. Processes are found through psutil; the process name must match exactly, case included, the command line is joined into one string and tested in the same way, and access denied on a command line produces a warning and no finding for that process.

What Stays Hidden on a Finding Line

A matched dictionary value is public dictionary material and stays visible in the Value field of its own finding. Every other value shaped token on that line is replaced by a mask. Tokens after an equals sign or a colon are masked, quoted tokens are masked, and tokens after password style flags on a command line are masked. A non default secret sharing the line therefore does not print in clear.

How a Run Ends

A configuration that cannot be loaded ends the run at exit 1; a missing file, a bad YAML file, and a schema failure all end there. Findings end the run at exit 1, and a failed scan for a missing configured file ends it at exit 1. A clean run with no findings and no failed file ends at exit 0. The verbose option turns on debug logging and changes no result. # confhard-DefaultCredChecker

Checks common configuration files (e.g., `config.ini`, `.env`, common database connection files) and running processes for default or weak credentials. Uses a built-in dictionary of common credentials and regular expressions to identify potential vulnerabilities. Findings name the matched default credential, which is public dictionary material, but the Line Content and Command Line fields are shown with every other value shaped token masked, so a non-default password sharing the line does not print in clear. - Focused on Automates the hardening of system and application configurations based on defined policies. Reads configuration files (e.g., YAML, JSON) and uses predefined rules (e.g., CIS benchmarks) to identify and remediate insecure settings. Provides tools to validate configuration changes and generate reports on compliance. It focuses on automation, not vulnerability detection. It should not alter the system or application without confirmation.
